`task rounds:rebuild IMAGE=clips/<slug>-<ms>.mp4` restores one round's clip: it reads the round's provenance from D1, re-cuts from the corpus with the same ffmpeg invocation that made it, and replaces the object under the same key. The moment being in the filename is what makes that land the same footage at the same URL — three shipped things already assumed the command existed, including the year-long `immutable` cache header the clips endpoint sets.
